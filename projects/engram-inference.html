Fast inference for DeepSeek Engrams

An open-source implementation of the Engram architecture, and the scheduling and memory work that made it practical to serve.

14 Sep 2026 PyTorch · CUDA · Distributed inference Code

The problem

DeepSeek's Engram architecture adds a module to the transformer that looks up stored memory instead of recomputing it. When I started, there was no public implementation. A straightforward one is also slow: on a large model sharded across GPUs, the Engram module spends most of its time waiting on memory movement.

What I built

First, a complete open-source implementation of the architecture, including manifold-constrained hyper-connections (mHC), mixture-of-experts layers and multi-head attention. Then two systems pieces aimed at the Engram module's cost:

  • A scheduler that overlaps Engram lookups with the rest of the forward pass, so GPUs aren't idle while memory is fetched.
  • A custom CPU/GPU memory allocator that decides which Engram tables live in GPU memory and which stay in host memory, to keep transfers off the critical path.

Together these made inference 44× faster than the baseline implementation on the same sharded setup.

The full report covers the benchmark setup, ablations for each optimization, and where the remaining time goes.
